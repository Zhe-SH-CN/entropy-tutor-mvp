# 产品范围与需求覆盖

参考基线：《AI 原生家教平台 MVP PRD v0.2》。本文用于区分已实现行为、沙箱能力和明确不在 Demo 范围内的事项，不用于证明商业效果。

状态定义：

- **已实现**：代码和自动化验证覆盖，可从真实入口操作。
- **沙箱**：内部状态机完整，但外部效果由模拟适配器产生。
- **未包含**：不属于当前 Demo 能力，不得由相邻功能推断为完成。

## 家长、教师与运营流程

| 范围                            | 状态   | 实现边界                                            |
| ------------------------------- | ------ | --------------------------------------------------- |
| 三角色统一全栈入口              | 已实现 | `/server-demo`；早期 localStorage 页面仅作界面切片  |
| 登录、会话、CSRF、资源授权      | 已实现 | Argon2id、随机会话哈希、HttpOnly Cookie、服务端授权 |
| 需求创建、Mock 结构化、家长确认 | 已实现 | 未确认需求不能进入推荐                              |
| 教师档案与运营审核              | 已实现 | 待审核档案来自合成种子，不含公开入驻表单            |
| 可授时间与容量                  | 已实现 | 结构化时间段和新鲜度过滤，不是第三方日历同步        |

| 见面改期、取消、no-show         | 已实现 | 异常事实独立追加，会议地址为沙箱                    |

| 排课、记课与课次确认            | 已实现 | 教师记课后需家长或运营确认                          |

| 报告发送与家长已读              | 已实现 | 站内可见性和已读记录，不含短信、微信或邮件          |
| 继续、暂停、更换教师            | 已实现 | 更换教师生成关联原需求的新草稿                      |
| 运营异常队列                    | 已实现 | 邀请、Worker 和业务异常集中查看                     |
| 桌面与移动端                    | 已实现 | Chromium 桌面与移动视口验证                         |

## 发布边界

内部 Demo 的“已实现”表示产品流程和工程闭环可用，不表示付费转化、续课率、学习效果、收入目标或生产可靠性已经成立。
